FLY.IO DEPLOY (same stack as local; Dockerfile-based, portable to Railway etc.)
==============================================================================

Layout:
  deploy/
    docker/          <- Dockerfiles (db, supavisor, meta, analytics, studio) — used by Fly & Railway
    fly/             <- Fly-only: fly.toml per app, Kong Dockerfile + config
    railway/         <- Railway notes (see README there)
    set-secrets-from-env.sh   <- Sync docker/supabase/.env to Fly secrets

Prereqs: flyctl installed, fly auth login, one org. Use region bom for all apps (FLY_ORG=commandra).

--- 1. DB ---
# From docker/supabase/:
cd deploy/fly/db
fly launch --no-deploy --copy-config --name commandra-db --region bom
fly volumes create pgdata --size 10 --region bom
cd ../..
./set-secrets-from-env.sh db
cd fly/db && FLY_ORG=commandra fly deploy -a commandra-db --primary-region bom
cd ../..
# Wait: fly status

--- 2. Supavisor ---
cd fly/supavisor
fly launch --no-deploy --copy-config --name commandra-supavisor --region bom
cd ../..

--- 8. Commandra prod DATABASE_URL ---
postgresql://postgres.commandra:YOUR_POSTGRES_PASSWORD@commandra-supavisor.flycast:5432/postgres
(Use the same POSTGRES_PASSWORD as in docker/supabase/.env. Get host from: fly status -a commandra-supavisor.)

--- 9. Migrations ---
DATABASE_URL="postgresql://postgres.commandra:PASSWORD@commandra-supavisor.flycast:5432/postgres" pnpm db:migrate

--- 10. Studio ---
https://commandra-kong.fly.dev (or https://db.commandra.app after step 7). Login: DASHBOARD_USERNAME / DASHBOARD_PASSWORD from .env.

Secrets: run ./set-secrets-from-env.sh (from deploy/) or set in Fly UI per app — see SECRETS-FOR-UI.txt for the list.

--- High availability (2 machines) ---
- DB: 1 machine only (single volume; for 2-node Postgres you’d need replication).
- Kong: fly.toml has min_machines_running = 2.
- Other stateless apps (supavisor, meta, studio, analytics): run when desired:
  fly scale count 2 -a commandra-supavisor
  fly scale count 2 -a commandra-meta
  (etc.)
