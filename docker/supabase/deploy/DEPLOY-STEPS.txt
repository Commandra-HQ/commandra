RAILWAY DEPLOY — self-hosted Supabase (same Dockerfiles as local)
================================================================

Primary guide: deploy/railway/PROVISION.md
Two projects (Commandra + Commandra Dev): deploy/railway/SETUP-TWO-PROJECTS.md
Secrets:       deploy/RAILWAY-SECRETS-CHECKLIST.md
Variables CLI: deploy/set-railway-variables-from-env.sh (from deploy/, after railway link)
DNS cutover:   deploy/DNS-CUTOVER.md

Layout:
  deploy/
    docker/     <- Dockerfiles (db, supavisor, meta, analytics, studio)
    kong/       <- Kong Dockerfile + kong.yml (platform-agnostic)
    railway/    <- railway.toml per service (paths from commandra repo root)
    set-railway-variables-from-env.sh <- Railway variables from docker/supabase/.env

Quick start (Railway):
1. In Railway, add 6 services from the Commandra GitHub repo.
2. For each service, set Config File Path to the matching file under deploy/railway/<name>/railway.toml (see PROVISION.md table).
3. Add a volume on supabase-db; enable private networking across all 6.
4. Set variables per RAILWAY-SECRETS-CHECKLIST.md + PROVISION.md “Non-secret env”.
5. Edit deploy/kong/kong.yml upstream URLs for meta/studio; deploy supabase-kong; attach public domain (port 8000).
6. Update commandra api env (DATABASE_URL, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY); railway up --service api.

Commandra app (API + dashboard) deploy from repo root:
  cd /path/to/commandra && railway up --service api && railway up --service web

Landing page (separate folder in monorepo):
  cd /path/to/commandra-hq/landing-page && railway up --service <landing-service-name>

Each deploy/railway/*/railway.toml sets conservative memory caps; raise supabase-db first if Postgres OOMs (see PROVISION.md).
